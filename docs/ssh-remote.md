# SSH 远端开发

一个窗口同时连接本机和一台服务器，可保存多条 SSH 连接。收藏记录不等于在线环境，切换服务器需要明确确认；普通切换不会停止原服务器任务。添加项目时选择“本机项目”或“远端项目”；项目和会话固定属于当时的环境，切项目不会断开另一边。远端日常空间与项目使用服务器图标标明归属，悬停可查看服务器；断线仍保留图标。设置和通知显示所属环境，两边同名目录仍是两个项目。

## 首次连接

先在系统终端准备具体 SSH Host 别名，用系统 OpenSSH 确认密钥或 ssh-agent 认证和主机指纹，确保非交互连接无需输入。Percho 不接管密码、首次主机指纹确认或 SSH 配置文件。

在“设置 → SSH 连接”点击“添加”，单选已有别名，再点“添加并连接”；手动添加也只填写系统 SSH 配置中的具体 Host 别名。选择本身不检测、不联网；发现/刷新只读取本机用户、系统配置及 Include，不执行 ssh、Match exec 或读取 IdentityFile。候选也可能是 Git 服务或当前条件下不适用的主机，发现失败不阻断手动输入。

添加先保存记录，再进入行内等待；失败或取消保留收藏，行内可重试。另一台服务器已连接时，先确认切换，再释放原桌面链路、连接目标。关闭设置不取消执行中的连接，返回可继续查看状态；需要安装确认但已经离开设置时不抢焦点，返回点击“继续安装”。

平台、Node 与发行包前提及安装维护规则见[构建发布的 SSH 运行包](build-release.md#ssh-运行包)。缺包时下载并展示真实版本、大小与安装目录，明确确认后才上传安装；关闭安装确认会撤销该次授权。已有兼容服务直接连接，不强制更新。旧记录若没有保存实际地址，需先人工核验当前主机/用户/端口，地址确认不代替安装授权。

连接成功后点击该行“添加远端项目”，填写服务器上的绝对目录，检查并信任后添加。技术信息与重新检测收进“连接详情”，检测不会断开另一台活动服务器。路径按服务器文件系统解释，不需要本机 clone。删除连接只移除本机连接资料，旧项目仍保留原归属；另一台服务器的同名目录不会自动接管旧会话。

## 工作与设置

模型请求、工具、扩展、MCP 与子代理都运行在所属环境。设置页明确选择本机或远端，远端单独准备 provider、API key 和项目依赖。本机界面插件的授权范围覆盖整个工作台；本机 LAN 页面仅显示本机内容。具体信任与数据边界见[架构说明](architecture.md)。

远端普通文件只能复制路径后在服务器打开。Git、diff、图片和内容型会话导出使用所属后端；导出完整生成后再选择本机保存位置。首版没有通用远端文件浏览、下载或交互终端。

## 断线与停止

切到本机、断网、断开连接或退出桌面都不停止远端任务。需要批准或输入时服务等待；后台提醒不会自动切走当前项目。重连先核验服务端仍然待决的请求，再允许回答。构造中的会话也可能要求扩展输入，此时点击来源提醒即可处理，不需要创建另一份会话。

重启应用只自动尝试最后成功连接的服务器，并经过已有信任门禁；不会遍历全部收藏，也不会在后台自动安装。手动断开/取消只停止本次运行的自动尝试，不改变重启策略。

明确停止请在已连接行的更多菜单选择“停止远端服务”，单独确认后等待退出确认。停止请求发出后不可取消，失败或超时会显示停止未确认；更新必须重新核验真实退出与所有权释放，删收藏、换别名或重启不能绕过检查。仅 SSH 退出、套接字文件消失或收到停止请求的确认，都不代表资源已清理完。解除“停止未确认”还需真实退出确认或只读取得已有私有服务所有者锁的证据；安装时仍会重新核验并实际获取安装锁与所有者锁。服务被其他桌面控制时返回占用，不会强行接管。

服务或主机崩溃后只恢复保存的历史，不自动重做上一条指令。提交后丢失确认会显示结果未知，可核查原回执、JSONL、轨迹与实际文件；没有记录也不能证明从未执行。不要据此重复发送有副作用的操作。
