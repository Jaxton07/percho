# 会话图片：数据归属与备份

## 模型输入与历史展示分开

发送、排队、撤回和重发必须保留真实图片输入。历史界面使用的轻量引用不能直接作为模型图片；投影展示数据不能改写SDK原始记录。用户附件和read工具图片也不能被展示工具的存储优化改变。

图片按来源环境、真实会话和记录定位，不能依赖时间戳、可重复的toolCallId或当前活跃页面猜测归属。远端图片读取失败不能回退读取本机同名路径。分叉复制的详情可能仍携带父会话标记，读取和导出须以当前真实所有者为准。

## 装载代次不等于图片版本

每次打开实例的握手标识用于隔离旧ACK、取消和迟到事件；图片来源版本则用于判断内容是否未变、能否跨GC复用。不能把两者合成一个代次，否则会造成旧事件放行新实例，或每次卸载后都重复取图。

视图卸载应撤销URL和订阅、释放完整来源视图；仍有效的有界缩略图缓存可以保留。真正删除、环境身份改变或断开必须定向失效，不能影响其他环境。在途读取被取消订阅后，实际请求结束前仍占并发槽，迟到响应不能覆盖新请求。

## 检视不拥有运行者

子代理只读检视不能创建第二套模型或扩展运行上下文。关闭、GC或重新装载检视不能停止真正运行者、派发其shutdown，或撤销其媒体所有权。

真正删除运行会话则必须等待写者停止和完整收尾；仅等待SDK abort不一定足够，否则文件可能在删除后被重建。无法确认收尾时应拒绝删除，而不是冒险继续。

## 私有媒体、分叉与导出

外置展示图按原始字节存储，不用缩略图代替原图。文件操作以实际会话所有权为边界；受控目录、链接拒绝和完整性校验不能只依赖界面参数。

分叉先准备媒体及不可发现的候选，再发布完整会话，不能改变在册源manager的身份。GC不是删除，不清除持久媒体。分叉、打开、删除、改名、导出和维护共用文件操作门；冲突应明确失败，不能并发重写。

后台预览收到结果不代表已经收尾；完成态须晚于worker退出和文件门释放，否则用户按完成回执立即整理仍会撞到旧锁。

自包含JSONL/HTML导出在副本中回填原图，不能修改源文件。缺图、校验失败或超过传输预算必须报错，不能返回缺图成功。HTML回填不代表扩展了SDK模板原有的展示能力。

## 备份与降级

只复制引用JSONL不是完整备份：应携带整个agent数据目录，或使用自包含导出。写入外置图片引用后，不能直接降级到不识别该存储格式的版本。

持久媒体随真正删除会话清理；关闭页面和内存回收不应删除原图。旧文件整理、原件备份和恢复必须由用户显式发起，不随启动或切会话自动迁移。独立原件备份不会随关闭或删除会话自动销毁，处理敏感内容时也须自行保管这些副本。未完成事务先检查恢复；整理后已追加或变化的文件不能直接用旧备份覆盖。
