# 用户级数据隔离与升级迁移

Percho 正式本机 agent 使用 `~/.percho/agent`，开发/预览使用 `~/.percho/agent-dev`，内测版使用 `~/.percho/agent-beta`。包含会话/轨迹、账号、模型、MCP、资源、权限和信任；与 Pi CLI 默认 `~/.pi/agent` 分离。正式与已有开发版的 Electron userData 和默认日常目录 `~/.percho/daily` 不搬迁。

独立身份的 `Percho Beta` 使用自己的 Electron userData（macOS 为 `~/Library/Application Support/Percho Beta/`），日常空间为 `<agent-beta>/daily`，UI 插件只使用其 userData，不创建全局插件别名。首次启动不会自动导入正式版或 Pi CLI 数据；旧内测包曾使用正式身份，其数据仍保留在原位置。明确传入 `PERCHO_AGENT_DIR` 或 `--user-data-dir` 时使用指定路径，测试应同时隔离两者。三套应用身份和打包入口见[构建发布](build-release.md)。

## 频道数据归属

每个执行端 agent 数据根按需使用一个频道数据库及其标记，位于 `<agent>/channels/`；频道、消息、成员和阅读位置在库内按项目隔离。本机各版本、自定义根及远端各自独立。频道不向项目写入数据或修改忽略规则，也不迁移、读取或自动清理旧项目内频道文件。

项目目录缺失不删除频道或会话历史；历史维护使用已保存的项目绑定，无绑定时使用会话工作目录的字面路径，不要求目录存在。恢复原路径后可继续使用原频道，不自动创建目录或追踪改名。单条归档的会话文件缺失且无频道维护凭据时，保留归档与禁止打开的保护并暂缓恢复，不阻塞其他项目；权限、身份冲突和数据库级损坏不按此降级，仍可能阻止依赖它们的操作。

## 首次启动

数据准备与工作台使用同一个窗口、同一份开屏 DOM。已有有效迁移记录的启动只显示品牌开屏，不挂载设置页；只有需要选择、采用已有目录或处理错误时才显示设置。数据准备完成不等于业务已就绪，须等主进程装配业务 IPC 后才在原文档导入工作台，不通过重载页面衔接。开屏兜底只在工作台可挂载后计时，不能令迁移中的等待或错误页超时进入工作台。

目标不存在且探测到旧同模式目录时，先选择导入或全新开始。选择导入后才完整扫描，展示数量、外部依赖和跳过警告，再明确确认复制；导入前关闭旧 Percho 和正在使用源目录的 Pi CLI。全新开始在持锁复查时也不扫描旧内容、不读取旧设置。复制可能包含 CLI 历史和账号，因为来源已经混合；源不移动、不删除。无旧目录时自动初始化，空旧目录仍可作为候选展示选择。目标已经存在（包括空目录）时只允许明确采用，不自动合并或覆盖。想重新导入，须退出后先另行备份并移走目标，不能覆盖已经使用过的新数据。

全新开始只独立于旧内容，不绕过目录隔离校验。旧源根本身为失效链接、根或祖先不能解析、另一保留旧根不能规范化时，仍会阻止初始化；不能将路径校验错误当作没有旧数据。

复制使用同父暂存、内容校验和 rename 发布。实际复制快照与用户确认快照直接比较，复制后再次验证；源根身份、跳过链接及资源设置变化也会使确认失效。历史 JSONL/轨迹逐字节保留，包括无效行；不是一次历史格式修复。已知旧会话路径通过本机入口映射到迁入文件，子代理仍只读。正常打开、分叉、改名、导出或删除不会因此重新写旧会话文件。源变化、复制错误、坏记录会明确中止；不能把权限错误当作无旧数据。

仅旧根下 `skills`、`extensions`、`prompts`、`themes` 的失效资源链接可在警告后跳过，包含这些根链接及普通目录内各层链接。须确认链接本身未变、仅目标不存在；权限错误、链接循环、链接身份不可靠及普通文件消失仍中止。核心数据和未知目录没有该豁免。有效链接保留既有重定位/外部依赖规则，不递归遍历外部目标树。警告详情与仍共享的外部依赖分开展示，原链接不修改；确认后清单保存在导入记录的可选 `warnings` 字段中，旧记录无需补字段。该清单不验证设置中每个显式资源引用，也不触发自动补装。

已知资源配置仅局部修改路径并保留 JSONC 注释。核心配置及会话的外部链接阻止导入；用户资源的显式外部依赖会列明，它们仍可能共享。复制的 OAuth 凭据可能需要重新登录；迁移不执行扩展、凭据命令或安装钩子，不联网补包。

桌面导航先保留带迁移 ID 的原件 `.before-agent-import-<id>.bak`，再严格读取并修改已知字段。损坏/不可读不会按默认值覆盖。发布后修正失败时保留新 agent，下次只继续引用修正，不重新复制。SDK 会话 ID、正文、项目 cwd 和远端引用保持不变；如果项目 cwd 位于旧 agent 树内，恢复执行前会拒绝并要求用户先处理项目位置。

## 自定义路径与隔离测试

用绝对 `PERCHO_AGENT_DIR`（支持 `~`）覆盖 Percho agent；不会自动推测或导入旧数据。只有旧的 `PI_CODING_AGENT_DIR` 时启动会中止，须移除旧变量或改用新变量，避免测试丢失隔离后误写正式目录。SDK 内部和独立 SDK 冒烟脚本仍可使用原变量，那不是桌面启动参数。

自定义目录启动的日常空间位于 `<agent>/daily`，并且不会创建/修改全局 `~/.percho/ui-plugins` 别名；插件实际数据仍在该实例 userData。测试还必须传独立 `--user-data-dir`，防止窗口偏好、插件和 SSH 资料串入正式版。默认正式/开发日常目录规则保持兼容。

迁移测试使用纯路径输入与合成目录，不修改 HOME 环境变量、真实凭据、真实会话或云服务器。不同平台路径规则的单测不等同于实际平台的 ACL/链接/启动验收。

## 失败与恢复

发布前扫描错误可以修复后重试或返回选择；复制失败须先结束任务并释放锁，才能返回选择。锁释放失败时保留原错误及暂存位置，禁止在本次流程中启动另一项初始化；须退出排查，不能用返回或重试绕过。扫描取消后的旧结果不会覆盖新选择，导入重试总是重新扫描并确认，不自动降级为全新开始。失败时通过错误详情披露保留暂存的位置（`.agent-import-<id>` 或 `.agent-empty-<id>`），不自动删除；取消退出也会保留暂存。先确认源和完整目标/备份可用，再自行清理不再需要的暂存；源若被误删，这些副本可能是恢复依据。重试会创建新副本，因此需要足够磁盘空间。不要把半份暂存直接改名为正式目标。

取消或错误恰逢发布完成时，以磁盘上的存储记录为准。导航引用修正失败只继续修正，不重导；工作台启动失败须退出重启，不提供全新开始来覆盖已发布数据。同目标初始化遵守同一锁协议；现有 rename 发布不保证抵御不遵守锁协议的外部进程在最后检查后创建空目标的竞态。

迁移记录 `.percho-local-storage.json` 与目标一起发布；不要删记录来强迫重新迁移。它不是长期全树校验库，正常会话更新后摘要变化是预期行为。应用崩溃恢复不等同于对所有设备断电故障的持久性保证。

旧目录保留不代表无损回滚：降级旧版将看到旧数据，新旧数据会分叉，不自动反向同步。恢复前退出相关进程，分别备份新旧目录及 userData，人工选择，不覆盖唯一副本。

## 隔离边界

- 项目 `.pi/`、`.agents/skills` 和项目指令仍按原信任规则兼容，修改同一项目配置可能影响 CLI。
- 用户显式外部资源、自写代码、系统环境凭据及账号本身不因目录分开而沙箱化。
- 同机同用户的桌面与 daemon 不能使用同一 agent。远端 `environment.json` 与本机存储标记互斥，即便服务已停止也不自动接管；选择不同 agent/runtime 根。旧版远端不认识本机标记，不支持这种同目录共存。
