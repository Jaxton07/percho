# 用户级数据隔离与升级迁移

Percho 正式本机 agent 使用 `~/.percho/agent`，开发/预览使用 `~/.percho/agent-dev`。包含会话/轨迹、账号、模型、MCP、资源、权限和信任；与 Pi CLI 默认 `~/.pi/agent` 分离。Electron userData 和默认日常目录 `~/.percho/daily` 不搬迁。

## 首次启动

数据准备与工作台使用同一个窗口、同一份开屏 DOM。已有有效迁移记录的启动只显示品牌开屏，不挂载设置页；只有需要选择、采用已有目录或处理错误时才显示设置。数据准备完成不等于业务已就绪，须等主进程装配业务 IPC 后才在原文档导入工作台，不通过重载页面衔接。开屏兜底只在工作台可挂载后计时，不能令迁移中的等待或错误页超时进入工作台。

目标不存在且有旧同模式数据时，关闭旧 Percho 和正在使用源目录的 Pi CLI，再选择复制或空目录。复制可能包含 CLI 历史和账号，因为来源已经混合；源不移动、不删除。目标已经存在（包括空目录）时只允许明确采用，不自动合并或覆盖。想重新导入，须退出后先另行备份并移走目标，不能覆盖已经使用过的新数据。

复制使用同父暂存、内容校验和 rename 发布。历史 JSONL/轨迹逐字节保留，包括无效行；不是一次历史格式修复。已知旧会话路径通过本机入口映射到迁入文件，子代理仍只读。正常打开、分叉、改名、导出或删除不会因此重新写旧会话文件。源变化、复制错误、坏记录会明确中止；不能把权限错误当作无旧数据。

已知资源配置仅局部修改路径并保留 JSONC 注释。核心配置及会话的外部链接阻止导入；用户资源的显式外部依赖会列明，它们仍可能共享。复制的 OAuth 凭据可能需要重新登录；迁移不执行扩展、凭据命令或安装钩子，不联网补包。

桌面导航先保留带迁移 ID 的原件 `.before-agent-import-<id>.bak`，再严格读取并修改已知字段。损坏/不可读不会按默认值覆盖。发布后修正失败时保留新 agent，下次只继续引用修正，不重新复制。SDK 会话 ID、正文、项目 cwd 和远端引用保持不变；如果项目 cwd 位于旧 agent 树内，恢复执行前会拒绝并要求用户先处理项目位置。

## 自定义路径与隔离测试

用绝对 `PERCHO_AGENT_DIR`（支持 `~`）覆盖 Percho agent；不会自动推测或导入旧数据。只有旧的 `PI_CODING_AGENT_DIR` 时启动会中止，须移除旧变量或改用新变量，避免测试丢失隔离后误写正式目录。SDK 内部和独立 SDK 冒烟脚本仍可使用原变量，那不是桌面启动参数。

自定义目录启动的日常空间位于 `<agent>/daily`，并且不会创建/修改全局 `~/.percho/ui-plugins` 别名；插件实际数据仍在该实例 userData。测试还必须传独立 `--user-data-dir`，防止窗口偏好、插件和 SSH 资料串入正式版。默认正式/开发日常目录规则保持兼容。

迁移测试使用纯路径输入与合成目录，不修改 HOME 环境变量、真实凭据、真实会话或云服务器。不同平台路径规则的单测不等同于实际平台的 ACL/链接/启动验收。

## 失败与恢复

失败或取消会显示保留暂存的位置（`.agent-import-<id>` 或 `.agent-empty-<id>`），不自动删除。先确认源和完整目标/备份可用，再自行清理不再需要的暂存；源若被误删，这些副本可能是恢复依据。重试会创建新副本，因此需要足够磁盘空间。不要把半份暂存直接改名为正式目标。

迁移记录 `.percho-local-storage.json` 与目标一起发布；不要删记录来强迫重新迁移。它不是长期全树校验库，正常会话更新后摘要变化是预期行为。应用崩溃恢复不等同于对所有设备断电故障的持久性保证。

旧目录保留不代表无损回滚：降级旧版将看到旧数据，新旧数据会分叉，不自动反向同步。恢复前退出相关进程，分别备份新旧目录及 userData，人工选择，不覆盖唯一副本。

## 隔离边界

- 项目 `.pi/`、`.agents/skills` 和项目指令仍按原信任规则兼容，修改同一项目配置可能影响 CLI。
- 用户显式外部资源、自写代码、系统环境凭据及账号本身不因目录分开而沙箱化。
- 同机同用户的桌面与 daemon 不能使用同一 agent。远端 `environment.json` 与本机存储标记互斥，即便服务已停止也不自动接管；选择不同 agent/runtime 根。旧版远端不认识本机标记，不支持这种同目录共存。
