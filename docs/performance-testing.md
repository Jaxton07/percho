# 本地交互与性能评测

统一入口在仓库根目录运行。它复用现有专项，负责隔离数据、串行采样、独立留档、基线比较和历史趋势；不替代真实账号、SSH、原生输入法或全平台验收。

```bash
npm run perf -- run --profile quick --label smoke
npm run perf -- run --profile full --label before-change
npm run perf -- history
```

`quick` 默认运行热切换/流式、大正文重开和 1000 会话目录预算；`full` 额外运行完整渲染/交互资源检查、五类 GC 重开、六类图片与 10000 会话目录预算。手动选择 `--suite` 不等于所有专项都有缩小模式。

| suite | 场景与模式 |
|---|---|
| `minimap` | 冻结构建版热切换、合成流式和输入采样；full 为三次独立启动、各三轮、每类 30 次切换，20/120/1000 轮历史 |
| `rendering` | 冻结构建版工具流式、增长、布局；full 使用独立应用分别执行性能与完整交互/资源检查，避免前一采集器退出影响后一场景 |
| `large-text` | 固定约 4.7MB 原始大段落，权威历史、页面和编辑器就绪后两次 rAF；真实卸载到 views=0 再重开，校验模型历史和渲染 DOM 的完整文本 |
| `switch` | Dev 五类真实合成历史，各 30 次卸载重开，不是热切换 |
| `images` | Dev 六类图片、原图/预览、资源和 GC/分叉/导出断言；源夹具先完成 SDK 配置初始化并 GC，只允许追记配置，不允许重写原数据，随后保留正常打开的完整字节不变断言；不测冷启动延迟 |
| `catalog` | 新 Node 进程与 Worker 的首次/已有索引刷新和归档投影；执行已有本机回归预算，不是 SLA |

只跑一个场景：

```bash
npm run perf -- run --suite large-text --profile full --label before-large-text
```

## 基线和趋势

运行结果默认保存在 `.local/test/performance/<运行编号>/`。每次新建目录，失败或中断也保留，不覆盖历史。目录编号见命令输出及 `history`。

- `manifest.json`：状态、提交、脏工作区标记、运行版本、匿名硬件标识、场景契约、参数、实际窗口及指标。
- `raw/`、`logs/`：原始采样和执行日志；暖机、异常样本不静默丢弃。失败前已完成的采样和校验失败的大正文耗时会保留检查点，CLI 在成功和失败收尾时均将已有检查点登记到 `rawFiles`。桌面启动日志独立归档到 `logs/`，不随成功工作树删除。
- `report.md`：该次结果。`passed` 表示执行和已有断言/预算通过，**不代表所有延迟都合格或没有退化**。
- `work/`：临时项目、agent、userData、冻结宿主和夹具；成功且确认退出后默认删除，失败/中断保留。`--keep-work` 可为诊断保留成功运行的工作树，注意磁盘占用。
- 根目录 `history.md` / `history.html`：历史列表及按相容组隔开的趋势；HTML 自包含，不启动服务。

基线必须显式设置，不会把最新一次自动变成新基线：

```bash
npm run perf -- baseline set <优化前运行编号>
npm run perf -- run --suite large-text --profile full --label after-large-text
npm run perf -- compare <优化后运行编号>
# 若基线含全部专项，可显式只比较共享场景：
npm run perf -- compare <优化后运行编号> --baseline <优化前运行编号> --suite large-text
```

比较和趋势只接受已结束、证据完整的有效记录：必须有本次 `raw/` 中实际存在的普通文件，禁止越界或符号链接；桌面场景必须有实际视口和 Electron 版本。只有无指标的图片功能记录可参与对应功能比较，但不能单独成为数值基线。比较会拒绝不同 profile、测量版本/哈希、夹具/参数、实际视口、模式和必要运行环境；产品提交或 SDK 版本变化是被测对象，会记录，不因此拒绝比较。不能把 Dev 与构建版、热切换与卸载重开混起来。选取共享 suite 不允许把失败整次运行的局部成功样本当成合格基线。

先提交需要留作可复现基线的源码，再采样。脏工作区会记录差异哈希，但未跟踪文件内容不打包，不能仅凭其哈希声称源码可重现。当前只支持相容性门禁和数值变化，没有擅自规定“涨 5% 就失败”。

## 旧记录导入

```bash
npm run perf -- import --file .local/tmp/minimap-final/final-built-3/minimap-results.json --suite minimap --label legacy-2026-11-05
```

支持已知原始 minimap 报告或数值汇总，复制原件到新记录的 `raw/imported.json`。缺失的提交、SDK/Node/Electron 和硬件信息保持未知；只作 `reference-only` 参考，不允许设为可靠基线或接入可比趋势。不能从当前机器补写旧环境信息来制造相容性。

## 隔离、拥有权与停止

- 所有新数据、HOME/XDG/临时目录都在当次 `work/` 下；不读正式凭据或复用正式会话。不搬动原有 `.local/tmp` 诊断目录。
- 私有 agent 对空合成项目使用拒绝信任策略，避免执行项目资源；不改变用户的信任设置、模型或插件开关。
- 桌面当前可靠支持 macOS；统一子进程树清理为 POSIX 实现，Windows 记录不支持/跳过，不能算通过。Node 目录专项可在合适的 POSIX 环境运行，不等于已完成 Linux/Windows 桌面验收。
- 构建在采样前执行一次；所有专项串行。不要同时跑测试、构建、其他基准或操作诊断窗口，否则数据受到干扰。
- 按 Ctrl+C 请求中断，保留已有记录，先取消并等待采样回调停止，再清理本次实际 Electron、包装进程、子进程组与应用登记；不会在回调还可能写文件时解锁。拥有权核验失败时拒绝终止未知 PID，记录清理失败，不冒险关闭用户应用。
- `.run-lock` 防止重叠运行。硬杀、机器重启或写盘失败可能留下锁/运行中记录；先检查锁中 PID 和对应进程确实已结束，再手动删除失效锁。工具不会擅自删除他人的锁或终止已有服务。
- `--json` 输出结构化结果；脚本调用可用 `node scripts/performance.mjs history --json` 或 `npm --silent run perf -- history --json`，避免 npm 自身的标题混入 JSON。退出码：完整成功 0，运行失败/部分不支持 1，不相容或参数错误 2，中断 130。记录的状态是权威，不只看某一脚本退出 0。

## 测量口径

双 rAF 不等于 OS 最终呈现；输入往返包含 CDP 与后续帧等待，不是纯编辑器耗时。合成流式不含模型/工具/网络生成。新进程或卸载重开不是物理冷盘。小样本大正文 p95 接近最大值，不是尾延迟保证；完整文本保留校验在计时结束后执行，不能据此认为已测到所有内容绘制完成。

测量口径 v2 的指纹同时绑定编排、汇总、检查点和测试专用诊断代码，而不只绑定夹具。缺少完整指纹的 v1 记录继续保留、可读，但只作参考，不再自动参与基线或同比趋势。升级工具后应重新采集并显式选择新基线；不把当前代码哈希倒填进历史，也不自动替换原有基线指针。检查点是辅助取证，不代替完整报告；资格检查要求至少一份结构有效、没有失败状态的对应专项报告。

历史中一秒级大段落重开与约 41ms 热切换不是同一路径。输入尖峰等未解释异常要保留并定位，不能筛掉首轮后才报告改善。

测试工具自身：`npm run test:perf`。实际桌面验收仍需调用上述 `run`；不要在采样时并行执行工具测试。
